# 歌单详情的按需分页与完整播放

对应 [规格 #3](https://github.com/SoundFieldLab/HyperPlayer/issues/3) 与 [任务 #5](https://github.com/SoundFieldLab/HyperPlayer/issues/5)。本实现只处理网易云与 QQ 歌单详情的首批展示、继续加载、完整播放准备和首页预热收敛，不改变播放、歌词、MV 或 HSE 的语义。

## 数据契约

- 歌单详情首批为目标 50 首，后续每批同样请求 50 首；网易云与 QQ 都向本地服务传递真实 `offset` / `limit`，服务再把页码传给上游。
- 响应返回当前 `offset`、有效页大小、下一页位置、总量、是否还有下一页和已映射歌曲。QQ 上游常返回少于请求数量的有效页，前端按实际上游页大小推进，不用请求值冒充。
- 网易云先轻量读取完整 `trackIds` 与顺序，再只为当前可见页取歌曲详情；QQ 通过歌单详情分页接口取当前页。缓存键包含平台、歌单和账号作用域，强制刷新只失效对应歌单。
- 只追加未见过的歌曲身份；空页、重叠页和迟到响应不会污染当前歌单。请求失败保留已加载内容并给出重试，不把失败页当成空歌单。

`src/hooks/usePlaylistPaging.ts` 是共享分页会话：它持有首批、下一页、总量、加载/错误、完整播放进度、取消代际、账号/平台/歌单失效和有界滚动位置。页面组件只决定如何展示和触发下一页。

简约、传统、探索和桌面入口共用同一契约。传统标签保留原来的“播放”按钮文本；播放全部时显示完整准备进度和取消入口。`定位当前歌曲` 会显式准备完整队列，再定位当前歌曲，避免只加载到目标页就截断后续歌曲。

首页不再在悬停或空闲时拉取整单。首页雷达模块只取首批 50 首，用户点击歌单后才请求首批详情。滚动接近列表底部时继续取下一页；点击播放全部或视频卡的直接播放才请求剩余页并构造完整队列。失败会保留部分队列并允许重试，不静默把首批冒充完整集合。

歌单返回播放页时恢复已加载分页和有界滚动位置；账号变化、平台切换和歌单删除会关闭旧会话。歌单曲目变化会使下一次完整加载强制刷新。

## 受控验收

固定生产构建、匿名隔离 profile 和受控 SDK／HTTP 上游下，四模式 × 网易云／QQ × 正常／慢网，各执行一次歌单打开与播放全部：

- 报告：`logs/perf/loading-paging-final3-20261116/report.json`
- 覆盖：16/16 运行、32/32 场景成功，0 失败。
- 构建 hash：`18e774c3795c45ca80b10609d176ecc776064f095620140d0baa3102c4e8c91c`
- 数据：160 首歌单；慢网为每个受控响应注入 180ms 延迟和 128KiB/s 速率。
- 歌单打开（跨模式/平台）：正常中位 1126ms（224–4504ms）；慢网中位 5852ms（3295–6745ms）。
- 播放全部动作：正常中位 425ms（379–655ms），首次 playing 中位 418ms（278–644ms）；慢网中位 7536ms（6728–7704ms），首次 playing 中位 7525ms（6719–7693ms）。

这些是单轮跨条件描述，不是稳定 SLO，也不表示真实平台服务拥有同样的延迟分布。固定响应可以验证分页、去重、取消代际、完整队列和界面接线；真实登录账号、平台私有歌单、真实 CDN 带宽与视觉手工验收仍需另行执行。

## 回归边界

`test/playlistPaging.test.tsx` 验证真实 `offset` / `limit`、首批外定位、跨页去重、完整队列从当前页继续而不重取首批。`test/modeIntegrationWiring.test.ts` 固定四模式共享分页会话与首页悬停预取移除。现有播放接线、歌单错误重试、桌面网格和传统模式测试继续覆盖界面行为。

性能回归时优先比较同条件的首批可用、完整播放首次可用、请求数和传输量。不得用首批请求变少换取播放范围截断、过渡失效或歌词／MV 回退；这些仍按硬性行为门槛验收。
