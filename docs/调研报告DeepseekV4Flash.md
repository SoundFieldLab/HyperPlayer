# 轻量级桌面音乐播放器技术选型调研报告


## 一、概述

本报告针对“开发一款轻量级桌面音乐播放器”这一目标，系统梳理了当前开源社区中主流的技术方案与实践项目。核心诉求是**避开 Electron 和 Tauri 这类重型框架**，在保证开发效率的前提下尽可能降低内存占用和安装包体积。

从开源社区的实践来看，轻量级音乐播放器的技术路线主要分为以下几类：

| 路线                 | 内存占用 | 跨平台     | 开发效率 | 典型项目                      |
| -------------------- | -------- | ---------- | -------- | ----------------------------- |
| **C++ 原生 (Win32)** | < 10MB   | 仅 Windows | 低       | BillyPro                      |
| **C++ + Qt**         | 30-80MB  | ★★★★★      | 中       | Fmusic_player、YAMP、Sayonara |
| **Rust + TUI/GUI**   | 10-40MB  | ★★★★★      | 中       | Presto、Termusic              |
| **Go + TUI/Wails**   | 15-50MB  | ★★★★★      | 高       | Podden、Audire                |
| **Python + PySide6** | 50-100MB | ★★★★       | ★★★★★    | desktop-music-player          |
| **系统 WebView**     | 20-50MB  | ★★★★       | 高       | webview-mpd-player            |
| **CEF**              | 80-200MB | ★★★★       | 低       | 网易云音乐(历史方案)          |


## 二、C++ 原生方案（极致轻量）

### 2.1 BillyPro

BillyPro 是一个极致的轻量级 Windows 音频播放器，完全使用纯原生 Win32 C++ 编写，基于 BASS 音频库。

**核心特点：**
- **内存占用 < 10MB**，CPU 占用接近 0%
- **启动速度 < 100ms**，无启动画面、无加载等待
- **纯原生 Win32**，直接编译为机器码，零托管运行时开销
- **音频格式支持全面**：MP3、FLAC、AAC、OGG、WAV、WMA、OPUS、AIFF、M4A、DTS 等
- **DSP 效果链**：Bass Boost（带真峰值限制器）、Mono 混音、音量归一化
- **便携式设计**：所有设置保存在 `BillyPro.ini` 中，无注册表污染

**技术栈：**
- 语言：C++
- 音频引擎：BASS 音频库
- UI：原生 Win32 API
- 构建：MSVC 编译器

**适用场景**：追求极致轻量、仅需支持 Windows 平台的项目。这是目前开源社区中内存占用最低的桌面音乐播放器之一。


## 三、C++ + Qt 方案（跨平台 + 成熟 UI）

Qt 是 C++ 生态中最成熟的跨平台 UI 框架，在音乐播放器领域有大量成功案例。

### 3.1 Fmusic_player

Fmusic_player 是一个基于 Qt 6 的跨平台音乐播放器，UI 采用 Fluent Design 风格。

**核心特点：**
- **跨平台支持**：Windows、macOS、Linux、Android、iOS
- **UI 与后端分离**：Qt QML 实现 UI，现代 C++ 实现核心功能
- **轻量级设计**：追求轻量、视觉一致、开源且功能丰富
- **本地播放**：支持 MP3、WAV、FLAC 等常见格式
- **歌词支持**：本地歌词文件与在线同步
- **主题支持**：亮色与暗色模式

**技术栈：**
- 语言：C++ 20
- 框架：Qt 6.8.1
- UI：QML + Fluent UI 样式
- 构建：CMake 3.20+、Conan 2.0+

### 3.2 YAMP (Yet Another Music Player)

YAMP 是一个性能导向、极致轻量的音乐播放器。

**核心特点：**
- **快速媒体扫描**：SQLite 驱动的音乐库，可处理数千首曲目
- **MPRIS 支持**：与系统媒体控制器和锁屏深度集成
- **现代技术栈**：Qt 6.8+、libmpv、TagLib
- **Replay Gain 支持**：通过标签完整支持回放增益
- **Last.fm 集成**：内置播放记录提交功能

**技术栈：**
- 语言：C++
- 框架：Qt 6、QML
- 音频引擎：libmpv
- 元数据：TagLib
- 数据库：SQLite

### 3.3 Sayonara

Sayonara 是一个为 Linux 设计的轻量级音频播放器。

**核心特点：**
- **轻量且功能丰富**：虽为轻量级播放器，但拥有大量功能
- **C++ + Qt 框架**：使用 GStreamer 作为音频后端
- **专注 Linux**：目前仅支持 Linux 平台

### 3.4 QT_Media_player

一个简洁的 Qt 6 音频播放器，展示 Qt 多媒体能力。

**核心特点：**
- 支持 MP3 播放，包含播放/暂停、曲目导航、随机播放和循环模式
- 显示元数据（标题、艺术家、专辑封面）
- **QML 现代 UI + C++ 后端逻辑**

**小结**：C++ + Qt 方案在跨平台能力和 UI 丰富度上表现最佳，内存占用通常控制在 30-80MB 之间，是“轻量级”与“功能完整”之间的良好平衡点。


## 四、Rust 方案（内存安全 + 高性能）

Rust 凭借内存安全和高性能特性，在终端音乐播放器领域尤为活跃。

### 4.1 Presto

Presto 是一个用 Rust 编写的简单 TUI 音乐播放器，具有 Vim 风格按键绑定。

**核心特点：**
- **键盘驱动的 TUI**：Vim 风格控制
- **目录扫描**：支持 mp3、flac、wav、ogg 等常见格式
- **MPRIS 集成**：支持 `playerctl` 和媒体键控制
- **元数据和歌词显示**：右侧面板显示元数据和内嵌歌词
- **状态持久化**：每个目录独立保存选择、过滤、随机播放、循环、音量等状态
- **模糊搜索**：`/` 过滤器支持逐词模糊匹配

**技术栈：**
- 语言：Rust
- 音频引擎：rodio
- TUI 框架：自建

### 4.2 Termusic

Termusic 是一个用 Rust 编写的终端音乐播放器，支持从 YouTube 等平台下载音乐并嵌入歌词和专辑封面。

### 4.3 shelltrax

基于 Rust 的终端音乐播放器，使用 ratatui 和 crossterm 构建，支持在终端中浏览文件系统、浏览音频文件并播放音乐。

**小结**：Rust 方案在内存安全与性能之间取得了很好的平衡，TUI 方案的内存占用可低至 10-20MB，非常适合偏好命令行操作的用户。


## 五、Go 方案（简单 + 高效部署）

Go 以其简单的语法、高效的并发模型和单二进制部署优势，在轻量级工具类应用中备受青睐。

### 5.1 Podden

Podden 是一个受 iPod Classic 启发的极简 TUI MP3 播放器。

**核心特点：**
- **TUI 界面**：使用 Bubble Tea 框架构建
- **视图丰富**：歌曲视图、专辑视图、艺术家视图、播放视图
- **同步歌词**：支持同步歌词显示
- **桌面通知**：跨平台桌面通知
- **音量控制**：支持音量调节
- **配置化**：可通过配置文件自定义外观

**技术栈：**
- 语言：Go 1.21+
- TUI 框架：Bubble Tea
- 音频引擎：beep
- 通知库：notificator

### 5.2 Audire

Audire 是一个极简音频播放器，使用 **Wails + Go + React** 构建。

**核心特点：**
- **Wails 框架**：Go 后端 + 前端技术（React）构建桌面应用
- **极简主义**：专注于核心播放功能与元数据显示
- **热重载开发**：Vite 开发服务器提供快速热重载

**技术栈：**
- 后端：Go
- 前端：React
- 框架：Wails

### 5.3 teamus

一个极简的终端音乐播放器，用 Go 编写，支持鼠标操作、进度条、播放/暂停等功能，可搜索音乐文件夹中的所有音频文件。

### 5.4 SubTUI

一个轻量级的终端音乐播放器，用于 Subsonic 兼容服务器，使用 Go 和 Bubble Tea 框架构建。

**小结**：Go 方案的开发效率高，部署简单（单二进制文件），适合快速构建原型和工具类应用。


## 六、Python + Qt 方案（开发效率最高）

Python 凭借丰富的生态和极高的开发效率，在快速原型和小型项目中非常受欢迎。

### 6.1 desktop-music-player

一个为 Windows 和 Linux 设计的桌面音频播放器，具有实时音频可视化。

**核心特点：**
- **跨平台**：支持 Windows 和 Linux
- **系统媒体键集成**：支持键盘媒体键控制播放
- **Mini 播放器**：弹出式迷你播放器窗口，带音频波形可视化
- **队列管理**：支持拖拽添加、重新排序和移除曲目
- **库扫描器**：自动发现音频文件并提取元数据（MP3、FLAC、WAV、OGG、M4A、AAC）
- **实时音频可视化**：波形显示与平滑动画

**技术栈：**
- UI：PySide6（Qt for Python）
- 音频播放：miniaudio
- 元数据：mutagen
- 音频分析：librosa + numpy
- 媒体键：Qt shortcuts (Windows) + MPRIS2 (Linux)

### 6.2 Macan Audio Player

一个现代化的 PySide6 音频播放器，支持多种流行格式。

**核心特点：**
- **格式支持广泛**：MP3、WAV、OGG、FLAC、AAC 等
- **同步歌词**：支持 .lrc 歌词自动跟随和手动锁定
- **暗色/亮色主题**：现代化配色
- **丰富功能**：标签编辑器、均衡器、DSP 管理器、音频转换器、FFT 可视化、专辑封面自动下载、全局热键、系统托盘控制、在线电台、播客流媒体

**技术栈：**
- UI：PySide6
- 音频引擎：FFmpeg

### 6.3 LrcMusicPlayer

一个基于 PySide6/PyQt6 的本地音乐播放器，专注于显示歌曲的内嵌歌词和歌曲信息，支持获取在线歌词，使用 SQLite3 数据库实现音乐检索。

**小结**：Python + Qt 方案的开发效率最高，生态丰富（mutagen 处理元数据、miniaudio/FFmpeg 处理音频），适合快速迭代。内存占用通常在 50-100MB，在可接受范围内。


## 七、Web 技术方案（CEF vs 系统 WebView）

如果希望使用 React 等 Web 技术构建 UI，有两个主要方向：CEF 和系统 WebView。

### 7.1 CEF（Chromium Embedded Framework）

CEF 将 Chromium 浏览器引擎嵌入到应用中。

**资源消耗对比（与 Electron）：**

| 场景         | CEF    | Electron |
| ------------ | ------ | -------- |
| 空白页面     | ~85MB  | ~180MB   |
| 复杂单页应用 | ~150MB | ~280MB   |
| 视频播放     | ~220MB | ~340MB   |

CEF 的内存占用通常比 Electron 低 30%-50%，但绝对数值依然很高（80-200MB）。

**技术挑战：**
- **MP3 支持需自行编译**：CEF 默认不包含 MP3 等专有格式的解码器，需要自行编译带编解码器的版本
- **开发复杂度高**：需处理 C++ 与 Web 前端的通信、多进程管理等底层细节
- **已有实践**：网易云音乐桌面端曾长期采用基于 CEF 的 Hybrid 架构

### 7.2 系统 WebView（推荐轻量级 Web UI 方案）

系统 WebView 不打包 Chromium，而是调用操作系统自带的 Web 渲染引擎。

**资源消耗：**
- 内存占用：**20-50MB**
- 应用体积：**20-40MB**

**代表项目：webview-mpd-player**

一个用 **Crystal + Webview** 构建的轻量级 MPD 客户端。

- **Web 界面**：用于控制 MPD 播放、管理播放列表、显示专辑封面
- **音乐库浏览器**：按艺术家/专辑组织
- **轻量级**：通过系统 WebView 实现，资源占用远低于 CEF/Electron
- **技术栈**：Crystal 语言 + Webview 库

**小结**：如果希望用 React 等 Web 技术构建 UI 且追求轻量级，**系统 WebView 是比 CEF 更优的选择**。它避免了打包完整 Chromium 带来的资源开销，同时保留了 Web 技术的开发效率。

### 9.2 针对性建议

**如果你追求“极致轻量 + 仅 Windows”：**
- 参考 **BillyPro** 的纯 Win32 C++ 方案
- 内存 < 10MB，启动 < 100ms，是开源社区中最轻量的方案

**如果你需要“跨平台 + 成熟 UI + 适中轻量”：**
- 参考 **Fmusic_player** 的 C++ + Qt 6 + QML 方案
- 或参考 **YAMP** 的 Qt 6 + libmpv + TagLib 方案

**如果你是 Python 开发者、追求快速开发：**
- 参考 **desktop-music-player**：PySide6 + miniaudio + mutagen
- 或 **Macan Audio Player**：PySide6 + FFmpeg，功能更丰富

**如果你是 Go 开发者、追求开发效率与部署便捷：**
- TUI 方向参考 **Podden**：Bubble Tea + beep
- GUI 方向参考 **Audire**：Wails + React

**如果你是 Rust 爱好者、追求内存安全：**
- TUI 方向参考 **Presto**：rodio + MPRIS 集成

**如果你希望用 React 等 Web 技术但不想用 Electron：**
- 优先考虑 **系统 WebView** 方案，参考 webview-mpd-player
- 内存 20-50MB，远低于 CEF 的 80-200MB
- **不推荐 CEF**：资源消耗依然很高，且需自行编译以支持 MP3


## 十、总结

综合来看，轻量级音乐播放器的技术选型可以根据以下维度快速决策：

1. **如果“轻量”是唯一不可妥协的指标** → **BillyPro 的 C++ 原生方案**（<10MB）
2. **如果需要在轻量与功能丰富之间取得平衡** → **C++ + Qt**（Fmusic_player、YAMP）
3. **如果追求开发效率和快速迭代** → **Python + PySide6**（desktop-music-player）
4. **如果偏好现代语言和内存安全** → **Rust TUI**（Presto）或 **Go + Wails**（Audire）
5. **如果希望用 Web 技术构建 UI** → **系统 WebView**（而非 CEF）

建议从上述项目中选择 1-2 个最接近需求的进行源码学习，借鉴其架构设计和音频处理实现，再结合自身技术栈偏好做出最终决策。
