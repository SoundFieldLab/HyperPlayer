## 8. 实测记录（2026-08-30，匿名链路 PoC）

**方法**：`temp/poc.cjs` —— 模块经 tsc 编译为 CJS 后由 Node 直接运行：ensureNetworkReady（公钥+匿名注册）→ searchSongs → getLyric → getSongUrl → 广度扫描。

**结果（全 PASS）**：搜索 5 条真实曲目+封面补齐 ✅ · 歌词 1014 字/33 行解析 ✅ · 播放地址命中 CDN（m7xx.music.126.net，standard 128kbps mp3）✅ · banner 8 条 ✅ · 热歌榜 200 条 ✅ · 歌单详情 ✅ · 匿名账号正确返回 null ✅ · 热门歌手 ✅ · MV 播放地址 ✅ · 歌手聚合 ✅ · 探索聚合 ✅

**PoC 发现并修复的缺陷（⚠→✅ 的代价）**：

1. **xeapiSign 密钥用法**：HMAC 密钥是 base64 **字面串直接作 UTF-8 字节**，不可先 base64 解码（服务端 "Invalid signature" 定位）
2. **midTransform XOR 步长**：密钥流取索引是 `i & 0x0f`（模 16），实现误写 `i % 0x0f`（模 15）——服务端直接断连（四象限交叉实验定位）
3. **外层 URL 路径**：三通道外层均需剥掉接口路径的 `/api` 前缀（`/weapi/v1/...`、`/eapi/v3/...`、`/xeapi/v1/...`），eapi 摘要内才保留完整 `/api/...` 路径
4. **weapi 通道 WAF 行为（未解之谜，已绕行）**：weapi 加密体与参考库逐字节等价（同 secret 确定性比对），经 undici fetch 发送仍被服务端 200 空响应拒绝（四象限交叉：我的头+lib 体 ✔、lib 头+我的体 ✘）；同体经 axios/https 传输正常。**决策：weapi 语义端点全部改走 eapi 通道**（协议库默认加密即 eapi，服务端 /api/* 全量兼容，实测 album/banner/personalized 等均通过）；`encryptWeapi` 保留于 crypto.ts 备用

**匿名注册的鸡生蛋问题（✔ 新增行为）**：xeapi `/api/register/anonimous` 在**无 MUSIC_A cookie 时被服务端空响应拒绝**（参考库依赖预置 token 的机器，全新环境同样会静默失败）。对策：会话引导优先读取 `os.tmpdir()/anonymous_token` 种子（与参考库行为一致）；无种子时注册静默降级——实测 search/lyric/song-url/banner 等核心端点**均不依赖 MUSIC_A**，仅部分写操作与个性化接口需要登录态。

**通道实测状态**：eapi ✅（search/lyric/detail/playlist/banner/artist/mv…）· xeapi ✅（song url/register）· weapi ⛔（WAF 空响应，已绕行 eapi）· 公开 GET ✅（歌手专辑/相关歌单）

### 启动链 ✅（session.ts）

1. 设备 id：52 位大写十六进制
2. xeapi 公钥：明文 POST `/api/gorilla/anti/crawler/security/key/get`（HMAC-SHA256 签名自校验，响应 AES-ECB 静态密钥解密）→ {publicKey, sk, version}

## 0.5 歌词格式族（`src/audio-source/lyrics/`，独立于音源）

- **YRC**（`yrc.ts`）：网易云/QRC 同构逐字格式，解析行为见 §5
- **LRC**（`lrc.ts`）：行级，多时间戳支持
- **TTML**（`ttml.ts`）：AMLL/Apple 方言子集（`<p begin end ttm:agent>`、`<span begin end ttm:role>`、x-translation/x-roman/x-bg、leadingSilence）；**正则实现，无 DOMParser 依赖**，Node/渲染进程双端可用
- **timing**（`timing.ts`）：括号补齐（仅整行首尾）→ 绝对起点校正 → 词间距修复 → 顺序归一化（140ms 兜底步长）→ 卡拉 OK 图元展开（Intl.Segmenter 图素切分）/渐进式均分兜底
- QRC **解密**不在范围：网易云歌词不经它；参考实现为 MIT 库 `qrc-decoder@1.0.2`（QQ 格式），未来接 QQ 源时直接 npm 依赖即可
- 明确排除：`song_url_match`/unblock 跨平台备用音源（违反 §4 付费内容规则与 D10 模块纯净性）

| 项 | 规范 |
|---|---|
| weapi ⛔（WAF 空响应，已绕行 eapi，算法保留备用）| `POST https://music.163.com/weapi/<path>`；payload = JSON 字符串。第一层 AES-128-CBC（固定 key `0CoJUm6Qyw8W8jud`，IV `0102030405060708`）→ base64；第二层 AES-128-CBC（随机 16 字符 secretKey，池 = 大小写字母+数字）→ base64 得 `params`；secretKey 反转后 RSA（无填充，公钥指数 `010001`，已知 2048 位模数）→ hex 得 `encSecKey`。表单提交两字段 |

## 3. 音质阶梯（✔ 参考项目验证的降级策略）

等级序：`standard < higher < exhigh < lossless < hires < jyeffect < sky < jymaster`

| 偏好 | 非 VIP 候选（按序降级） | VIP 候选 |
|---|---|---|
| standard | `[standard]` | `[standard]` |
| high / 其余非 VIP | `[exhigh, standard]` | `[exhigh, standard]` |
| very-high / lossless | 同上 | `[lossless, exhigh, standard]` |
| hi-res | 同上 | `[hires, lossless, exhigh, standard]` |
| auto / 默认 | 同上 | `[jymaster, hires, lossless, exhigh, standard]` |

**重试策略（✔）**：候选序第一位尝试 2 次、其余 1 次；单次调用超时 = 剩余预算夹在 `[300, 4500]ms`；两次尝试间隔 150ms；整体预算默认 16s。返回 `body` 但 `data[0].url` 为空时视为该候选失败，继续降级。

## 4. 付费内容规则（✔）

`fee === 1 || fee === 4`（VIP/购买曲目）：无有效 url 时**不得**使用任何跨平台/第三方备用音源，直接向上层报告 `url: null`（版权合规边界，不可突破）。

## 5. 歌词行为（✔）

- **总重试策略**：5 次，指数退避 `[300, 600, 1200, 2400, 4800]ms`，单次 10s 超时；全部失败返回**空歌词结构**（`lrc/tlyric/yrc/romalrc` 均空串，code 200），由上层决定降级来源
- **YRC 逐字格式**：行头 `[行开始ms,行时长ms]`，随后若干 `(字开始ms,字时长ms,0)文本` 段
- **解析规则（✔）**：
  1. `{` 开头的 JSON 元数据行（作词/作曲信息）跳过
  2. 行头正则必须匹配 `[数字,数字]`，否则跳过该行
  3. 时间戳段前的孤立前缀（如 `词:`、`曲:` 标签）剔除
  4. 纯数字/逗号/括号碎片（误匹配的时间戳残片）过滤，不作为词
  5. 无时间戳的词串：按字符数在「上一个有时间的词结束 → 下一个有时间的词开始」区间内线性分摊；区间不可得时按 `min(2400, max(280, 字符数×180))ms` 估算
  6. 空白 token 保留但时长为 0
- **LRC 行级格式**：`[mm:ss.xx]`（可多时间戳同行）；行时长按下一行开始时间推断
- 时间统一为**绝对毫秒**（实现内部约定，与参考项目的行内相对时间不同）

## 6. 模块边界（D21 Tauri 2 修订）

- **现有验证实现**：`src/audio-source/netease/`（TypeScript，使用 `node:crypto`、Node `fetch`、Buffer 和临时目录）；它已通过联网 PoC，是 Cleanroom 行为 oracle 和 Rust 迁移的等价测试基准，**不直接进入 Tauri WebView 运行时**
- **Tauri 终态实现**：网易云网络、Cookie、设备会话、weapi/eapi/xeapi 加密和写操作迁入 Rust 后端；Tauri 应用层只暴露受限 commands，不提供通用代理、任意 URL 或 Cookie 读写接口
- **可保留的 TypeScript**：`src/audio-source/lyrics/` 的 LRC/YRC/TTML 纯解析与时间轴逻辑不依赖 Node，可留在前端或按复用需求迁入 Rust
- **迁移验证**：Rust 实现必须以本规范和现有 TS PoC 为 oracle，逐端点做输入/输出、错误码、退避、音质降级、付费内容拦截和歌词解析等价测试
- **禁止 Node sidecar**：不在 Tauri 中额外携带 Node 运行时，避免 WebView2 + Rust + Node 三运行时和额外生命周期/打包复杂度
- 参考：`temp/netease-lyrics-code/` 只读；对 `@neteasecloudmusicapienhanced` 等第三方库**不引入运行时依赖**，协议行为独立实现
