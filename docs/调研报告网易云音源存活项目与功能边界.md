# 调研报告：仍存活的网易云第三方播放器与建议功能边界

> **决策状态（2026-08-30）**：本文的“匿名只读免费模式”是调研阶段的保守建议，已被 D22 的“网易云全能力接入”产品策略取代。D23 另行确定：VIP 缓存必须绑定登录账号，并在每次播放前由服务端实时确认同账号权益；下载/导出仍明确禁止。本文保留为风险与竞品参考，不是现行需求基线。

> 调研日期：2026-08-30  
> 用途：决定 HyperPlayer 是否以及以什么边界内置网易云音源。  
> 方法：只核对项目官方 GitHub、README、Release、源码和 Issue。项目仍存活只能证明该做法现实中仍有人采用，不能证明获得网易或版权方授权。

## 一、结论先行

截至 2026-08-30，**仍有多个活跃项目内置或调用网易云能力**：

- YesPlayMusic：仍维护，内置网易云登录、歌曲、歌词、MV，也有桌面端解灰；但明确不支持 MP3 下载/导出。
- AlgerMusicPlayer：仍维护，内置网易云、备用解析、下载、缓存、歌词和 MV，功能边界最激进。
- netease-cloud-music-gtk：非常活跃，使用网易云官方返回的歌曲 URL，支持账号已有权益，不做跨平台解灰；只有播放缓存，未发现导出下载。
- NeteaseCloudMusicApiEnhanced：活跃的 API 工程，包含大量网易云接口、解灰和下载 URL，但它本身不是播放器。
- MusicFree、洛雪：播放器仍活跃，但当前官方发行物不再默认内置网易云源，把音源交给外部插件/用户自定义源。

因此，**“内置网易云的项目仍然活着”是事实**；但最适合 HyperPlayer 的参考不是功能最激进的 Alger/SPlayer，而是：

> `netease-cloud-music-gtk` 的官方权限边界 + `MusicFree/洛雪` 的模块隔离方式 + `YesPlayMusic` 的“不提供 MP3 下载导出”。

你提出的方案——**普通用户只播放普通免费歌曲，不播放 VIP/付费/仅试听歌曲，不保存或导出本地 MP3**——能明显降低风险，也比不少仍存活项目更保守。它不能让风险归零，但作为产品策略是合理的。

## 三、HyperPlayer 建议采用的保守边界

### 建议首发启用

- 搜索歌曲、专辑、歌手、歌单和榜单
- 播放**服务器返回完整有效 URL 且明确非 VIP/非付费/非仅试听**的歌曲
- 歌词展示：LRC/YRC/翻译/罗马音
- 普通封面和基础元数据展示
- 公开歌单、排行榜、推荐新歌
- 仅内存缓冲或短时播放缓存；用户不可访问为普通音频文件
- 音源模块可在构建、设置和运行时整体关闭
- 明确标注“第三方非官方客户端，与网易云音乐无合作或隶属关系”

### 建议首发禁止

- **VIP、付费专辑、数字专辑、仅试听歌曲播放**，即使接口偶尔返回可用 URL 也主动拒绝
- Unblock、解灰、跨平台搜索匹配、备用音源替换
- 下载、另存为、导出 MP3/FLAC、批量下载
- 永久音频缓存、公开缓存目录、将缓存改后缀即可播放
- 云盘歌曲下载和云盘 URL 获取
- MV 下载
- 共享、内置或上传公共 Cookie
- 把付费内容标记伪装成免费内容
- 为失败歌曲寻找其他平台的同名替代资源

### 建议暂缓

- 网易账号登录：后续可加，但先只做匿名免费模式最稳
- 评论、私信、动态、关注、发评论、点赞等社交写操作
- 创建/删除/编辑网易歌单、上传封面
- 听歌打卡和行为上报
- 完整高清封面原图、评论头像等与播放无关的数据抓取

## 四、推荐的权限判断

不要只依赖 `fee` 一个字段。播放前至少同时检查：

```text
存在完整 URL
AND 非试听片段
AND fee 不属于 VIP/购买类
AND privilege.st >= 0
AND privilege.playMaxbr > 0
AND 没有 freeTrialInfo
AND 来源必须是网易官方 URL
```

建议标准化成明确结果：

```text
PlayableFree       // 普通免费完整播放
BlockedVip         // VIP / 会员歌曲
BlockedPaidAlbum   // 购买专辑 / 数字专辑
BlockedTrial       // 仅试听片段
BlockedCopyright   // 无版权 / 地区不可用 / 已下架
BlockedNoUrl       // 服务端无有效 URL
```

播放器遇到任何 `Blocked*` 状态时只显示原因，不回退、不匹配、不解灰。

## 五、缓存策略建议

“缓存”和“下载”必须分开：

- `stream cache`：仅为防卡顿，随机文件名、不可导出、限制大小和寿命，播放结束或退出后清理
- `offline copy`：离线可反复播放，属于用户可用副本，首发不做
- `export`：保存 MP3/FLAC 到用户目录，首发明确不做

若 Rust 音频引擎可以直接边下载边解码，首发甚至可以完全不落盘，只保留有限内存缓冲，这是最清楚的边界。

## 六、建议决策

建议 HyperPlayer 采用：

> **“匿名只读免费模式”首发**：只播放网易官方返回的免费完整 URL；禁 VIP、禁试听、禁下载、禁永久缓存、禁解灰、禁跨平台备用源；保留歌词和公开曲库浏览；网易模块可整体关闭。

它比 YesPlayMusic、Alger 和归档前 SPlayer 更保守，接近活跃的 netease-cloud-music-gtk 在音频权限上的做法，同时吸收 MusicFree/洛雪的模块隔离设计。

如果后续决定加账号登录，最多允许“用户账号在网易官方规则下本来就有的权益”，但不要把它表述成“支持 VIP 破解”，也不要将会员 URL 转成可下载文件。

## 七、必须记住的限制

- 有项目仍然运行，不代表网易或版权方授权这些项目。
- 禁 VIP 和禁下载能明显降低风险，但不能消除未授权接口调用和内容展示风险。
- Apache-2.0 只管 HyperPlayer 自有代码，不会把网易接口、歌曲、歌词或封面变成 Apache-2.0 内容。
- 这是产品边界调研，不是正式法律意见。正式公开发布前若项目已有明显用户量或商业化计划，应再做一次针对实际发行包的合规审查。
